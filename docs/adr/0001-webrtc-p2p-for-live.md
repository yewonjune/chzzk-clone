# 방송 송출은 WebRTC P2P(휴대폰 → 시청자 직접 연결)로 한다

방송은 휴대폰 브라우저가 시청자마다 WebRTC 연결을 직접 맺어 보내고, 서버는 WebSocket으로 연결 정보 교환(시그널링)만 맡는다. `gradlew bootRun`만으로 실행되어야 하고(ffmpeg·Docker 미디어 서버 같은 별도 설치 없음) 지연이 1초 미만이라는 점을 택했다. 그 대가로 휴대폰 업로드 대역폭 때문에 동시 시청자 수에 상한이 있고, 서버에 녹화가 남지 않는다.

## Considered Options

- **MediaRecorder → 서버 → ffmpeg → HLS**: 시청자 수 제한이 없고 녹화가 자연스럽지만, 서버에 ffmpeg가 필요하고 지연이 5~10초이며 iOS/안드로이드 코덱 차이를 처리해야 한다.
- **외부 미디어 서버(mediamtx 등, Docker)**: 가장 견고하지만 실행 환경에 Docker가 필요하다.

## Consequences

시청자가 많아지는 단계가 오면 송출 경로를 SFU나 미디어 서버로 바꿔야 한다. 이때 시그널링 메시지 형식과 방송·시청자 개념은 유지하고, 미디어 경로만 교체한다.
