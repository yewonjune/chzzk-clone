# 인증은 Spring Security 서버 세션(쿠키)으로 한다

화면·API·방송 WebSocket을 모두 같은 서버(같은 출처)가 제공하므로, 로그인 상태를 서버 세션에 두고 세션 쿠키로 식별한다. 쿠키는 WebSocket 연결 요청에도 자동으로 실려 와서 송출자가 누구인지 서버가 별도 장치 없이 알 수 있고, 로그아웃하면 서버에서 세션을 지워 즉시 무효화된다. 비밀번호는 BCrypt로 저장한다. 쿠키 기반이므로 상태를 바꾸는 요청에는 CSRF 토큰을 요구한다(토큰은 세션에 두고 `/api/auth/me`로 화면에 전달).

## Considered Options

- **JWT(Bearer 토큰)**: 서버가 상태를 갖지 않지만, 로그아웃 즉시 무효화를 하려면 차단 목록이 필요하고, 브라우저 저장 위치(XSS 노출)와 WebSocket 인증 방법을 따로 설계해야 한다. 서버 한 대인 지금 구조에서 얻는 이점이 없다.

## Consequences

서버를 여러 대로 늘리면 세션을 공유 저장소(Spring Session + Redis 등)로 옮겨야 한다.
