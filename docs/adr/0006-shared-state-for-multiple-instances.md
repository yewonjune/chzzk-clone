# 여러 인스턴스는 상태를 PostgreSQL·Redis·공유 볼륨에 두고, 방송 시그널링은 Redis pub/sub으로 중계한다

5단계에서 서버를 여러 인스턴스로 띄우고 부하에 따라 늘리고 줄인다. 그래서 인스턴스 메모리나 로컬 디스크에 있던 상태를 모두 밖으로 옮긴다. 기록(사용자·방송·다시보기·댓글·후원, 가짜 PG 결제)은 PostgreSQL, 로그인 세션과 방송의 실시간 상태(송출자 접속 여부, 시청자 목록)는 Redis, 업로드 영상은 모든 인스턴스가 마운트하는 공유 볼륨에 둔다. WebSocket 연결 자체는 옮길 수 없으므로 각 인스턴스는 자기에게 붙은 연결만 들고, 시그널링·댓글·후원·제목 변경 메시지는 방송별 Redis 채널로 주고받는다. `gradlew bootRun` 단일 인스턴스 실행(H2·로컬 디스크·메모리)은 기본 프로필로 계속 지원한다.

## Considered Options

- **방송 id 기준 스티키 라우팅**: 같은 방송의 연결을 프록시가 한 인스턴스로 모으면 코드 변경이 거의 없다. 그러나 인스턴스 수가 바뀌면 해시 배정이 바뀌어 새로 들어온 시청자가 송출자와 다른 인스턴스로 가고, 송출자가 붙은 인스턴스가 스케일 인되면 방 전체가 사라진다.
- **오브젝트 스토리지(MinIO)**: 실제 클라우드에 더 가깝지만 업로드·Range 재생 코드를 다시 짜야 한다. 로컬 단일 노드 클러스터에서는 공유 볼륨으로 충분하다.

## Consequences

"송출자가 있는가"를 인스턴스 메모리로 판단하던 코드(시작 시 방송 일괄 종료, 송출 연결 없는 방송 정리)는 Redis 기록 기준으로 바뀐다. 인스턴스 하나가 내려가도 방송이 끝나지 않도록 송출 연결이 끊긴 뒤 **재연결 유예**를 둔다.
